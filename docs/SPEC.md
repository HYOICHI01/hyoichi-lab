# HYOICHI Lab Webサイト実装仕様書 Ver.0.3

## 1. プロジェクト概要

**サイト名：HYOICHI Lab**

個人ゲーム開発およびVTuber活動を行う「標一 / HYOICHI」の公式サイト。

サイトの主軸は**個人ゲーム開発**とし、制作したゲーム・Webブラウザゲーム・現在開発中のゲームを紹介する。同時に、VTuber「標一
/ HYOICHI」の活動についても掲載する。

企業サイトのような複雑な構成にはせず、**個人で制作・更新・保守しやすいシンプルなサイト**を目指す。

## 9. GAMEページ

GAMEは、**HYOICHI Labサイト上で直接遊べるWebブラウザゲーム専用ページ**とする。
スマートフォン向けやSteamなど外部プラットフォームで入手する作品はPRODUCTSへ掲載し、GAMEには掲載しない。

掲載対象例：

- ROOM01 / ROOM02 / ROOM03
- 今後制作するHTML5 / Webブラウザゲーム

カードにはサムネイル、ゲームタイトル、ジャンル、短い説明、公開状態を掲載する。
公開済み作品にはPLAYボタンを設置し、サイト内のゲーム本体へ直接移動する。

例：ROOM01 → games/room01/

ゲーム本体が存在しない場合は、存在しないページへのリンクを有効にしない。
初期版は準備中表示と無効なPLAYボタンを使用できる。ゲームを増やす際はカードを追加する。

### 9-1. PRODUCTSページ

products.htmlを新しいメインページとして作成する。

PRODUCTSは、**Android / iOS / Steam等の外部プラットフォームで公開・販売するHYOICHI Labの作品を掲載するページ**とする。

主な対象：

- Android
- iOS
- Steam / PC

将来はゲーム以外のアプリ等も掲載できるよう、カードのジャンル欄は作品カテゴリにも使用できる構造にする。

作品カードには必要に応じて以下を掲載する：

- サムネイル
- タイトル
- ジャンル / カテゴリ
- 短い説明
- 対応プラットフォーム
- Google Playリンク
- App Storeリンク
- Steamリンク

対応プラットフォームは確定した情報だけを記載する。
各作品が実際に対応しているプラットフォーム・ストアだけを表示する。
Google Play・App Store・Steamの3項目を固定表示せず、ストア行は作品ごとに独立して追加・省略できる構造とする。

- Androidのみの作品：対応プラットフォームはAndroid、ストア欄はGoogle Playのみ。
- Steamのみの作品：対応プラットフォームはSteam / PC、ストア欄はSteamのみ。
- 複数対応の作品：実際に対応するプラットフォームとストアのみを列挙する。
- 非対応ストアの行は省略し、空行や「未定」の代替行を表示しない。ストア情報がない場合はストア欄全体を省略できる。

現在のサンプルカードはレイアウト確認用の例外として、3項目表示を維持してよい。
ストアURLが未確定の場合、架空のURLや動作しないリンクを作成しない。
初期版は明示したサンプルカードや準備中表示を使用できる。
作品個別の詳細ページは初期版では作成しない。

## 12. CONTACT

お問い合わせフォームを設置する。

必要項目：

``` text
お名前 *
メールアドレス *

メッセージ *

```

問い合わせ種別例：

``` text
ゲームについて
配信について
お仕事・ご依頼
不具合報告

```

最後に、

``` text
[ 送信する ]
```

ボタンを配置する。

### 注意

初期HTML制作時点では、フォームのデザイン・入力UIまで実装する。

実際のメール送信方法については、**公開先・フォームサービスを決定してから実装する**。

送信先メールアドレスをHTMLやJavaScript内へ不用意に露出させない。

公開時には、

-   入力チェック
-   スパム対策
-   CAPTCHA等の必要性
-   プライバシーポリシー
-   送信完了表示
-   エラー表示

を検討する。

## 19. スマートフォン・タブレット対応

PC版デザイン確認完了後、6ページすべてにレスポンシブ対応を実装済み。
確定したPC版を基本とし、HTML / CSS / Vanilla JavaScriptを維持する。

- 1040px以上：確定したPCレイアウトを基本的に維持。
- 769〜1039px：横型ナビを維持。最小幅制限を解除し、余白・列幅を補正。カードは2列。
- 768px以下：スマートフォン・小型タブレット向けの1カラム表示。カードは1列。
- 360px以下：タイトル・余白・TOPのCREATOR紹介を追加調整。
- 769〜1279pxのTOP立ち絵は透明余白による横はみ出しを防ぐため、拡大後と同じ高さを画像要素に設定する。

### 固定ヘッダーとメニュー

768px以下ではロゴを左、44pxのハンバーガーボタンを右に配置する。
Vanilla JavaScriptで開閉し、TOP / GAME / PRODUCTS / CREATOR / NEWS / CONTACTを表示する。
aria-controls・aria-expanded・開閉ラベルを使用し、現在ページのaria-currentを維持する。
閉じたメニューはhiddenで表示・Tab移動の対象から外す。
項目選択、Escape、ヘッダー外クリック、ヘッダー外へのフォーカス移動で閉じる。
Escape・項目選択時はボタンへフォーカスを戻す。画面幅の切替時は開閉状態とフォーカスを調整する。
メニュー内が画面高を超える場合は縦スクロール可能とする。
JavaScript無効時も折り返しナビゲーションを表示して各ページへ移動できるようにする。

### ページ別

TOPはコピー・立ち絵・クレジットを縦に配置し、全情報を維持する。
CREATORは立ち絵 → クレジット → プロフィールの順に配置する。
スマートフォンでは画像の拡大transformとクレジットの位置補正を解除し、通常フローで重なりを防ぐ。
NEWSは日付・カテゴリの下にタイトルと矢印を配置する。
CONTACTは幅を可変にし、入力文字16px・入力欄48px以上を確保する。
送信機能・同意チェックの未接続状態は維持する。
フッターはリンクを折り返す。横はみ出しは要素の幅・列・画像を調整し、ページ全体のoverflow-x: hiddenで隠さない。

### 確認対象

1440 / 1024 / 768 / 430 / 390 / 375pxを確認対象とする。
横スクロール、見切れ、固定ヘッダー、メニュー開閉・キーボード操作、
立ち絵とクレジットの分離、フォームの操作性を確認する。
コード検証と実ブラウザでの目視確認は区別し、未実施項目を完了扱いしない。

## 21. 実装時の重要事項

Codexは以下を優先すること。

1.  **初心者でも後から編集しやすいコードにする。**
2.  HTML/CSS/JavaScriptを必要以上に複雑化しない。
3.  クラス名を分かりやすくする。
4.  過度なライブラリ・依存関係を追加しない。
5.  ゲームやNEWSを後から追加しやすい構造にする。
6.  PC版を先に完成させる。
7.  PC版確認後にスマートフォン対応を行う。
8.  アクセシビリティを考慮する。
9.  画像には適切な`alt`を設定する。
10. キーボード操作時にもリンク・ボタンのフォーカス位置が分かるようにする。
11. 不要な巨大画像・JavaScriptを避け、軽量にする。
12. SEOの基本となる`title`、`description`等を各ページに設定できるようにする。
